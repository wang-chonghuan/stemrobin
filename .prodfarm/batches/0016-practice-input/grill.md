# Batch 0016-practice-input — grill 记录

本批为 seed 派生批，cap7 的人机 grill 由 seed STEMROBIN-116 的 cap11 自我 grill 满足（cap8 规定不再重跑 cap7）。以下为该 grill 的完整记录。

### cap11 自我 grill 记录（machine grills itself，无人在场）

**1. 可行性（带实况探测）**
- 已用 Playwright 驱动本地 3200 实测：三课全部可打开、可作答、可判分；提交 5 道题验证判分链路可用（测试账号 user_id=2）。
- 统计三课真实数据：65 道题、186 个作答部件，其中 **160 个（86%）标准答案就是一个普通数字**，17 个文本精确匹配，**代数表达式 0 个**。结论：当前线上产品里没有任何一个作答部件需要 LaTeX 数学键盘，而 100% 的作答框都强制使用它。
- 不引入新依赖可行：数字输入用原生 input，网格点选用已有的内联 SVG + React 事件，栈内已有 React 19 + Tailwind 4。

**2. 一致性（对照 charter）**
- goal.md「数学内容以中文为源语言」→ 默认中文与目标一致；这是对 STEMROBIN-111「默认英文」的人为反转，依据已由人在本会话中给出。
- engineering-rules「无谓依赖」铁律 → 全部草案禁止新增依赖，已写入各自 Constraints。
- redlines 第 2 条（生产数据）→ 交互规格入库走 ld-s10y-answer 既有 publish 路径，幂等 upsert 并保留既有答案键，不是破坏性写入。
- engineering-rules「SSOT」→ 交互规格与答案键同目录、同 lesson 粒度、同一条发布路径，不另起管线。

**3. 完备性**
- 仅改数字输入只覆盖 86% 的部件；剩下的痛点是 26 个无标签作答框（第 1 课全部用 `id` 而非文档规定的 `label`）、一次性判分、以及 11 道不判分题。三者分别由草案 2、3、4/5 覆盖。

**4. 约束挑战（这条是本次 grill 的主要产出）**
- 人要求「必须用 express 模式」。按 ticket-contract 的六条 express 准入谓词逐条评估：草案 1/2/3 六条全过 → express；草案 4（新增 `lesson-interactions@1` 契约与入库字段）违反谓词 2「无契约变更」，草案 5（坐标网格点选是全新的 UI 形态，本地无既有模式）违反谓词 3 → 二者只能 standard。
- 依据 ticket-contract 的**非对称规则**：「任何人都可以强制 standard；任何人都不能在谓词不成立时设为 express」。人的偏好不能覆盖失败的谓词。此项由规则本身裁定，不构成需要人裁决的 grill 泄漏，故不上升。

**5. batch 风险**
- 每张工单都要走 worktree + 验收 + 合并 + 重部署，10 张跑不完的风险高于价值。因此草案集收敛到 **5 张**，把额度留给批内自建的 fix。

### 明确延后的项（非静默截断，记录在案）
以下问题本次实测中确认存在，但不在人给定意图的核心（答题体验 + 技能改造）之内，留作后续 seed：
1. 第 1 课图形归类控件（6 小问 1 个框，且不判分）——最重的交互形态，单独一张 story 才够。
2. 错题本条目只显示「Book 5m / Exercise 5」，没有课名与题面。
3. 上一课/下一课按大纲走，从三课任一课点「下一课」会落到无内容的空卡。
4. 课文页底部 Save 与 Ask AI 是没有 onClick 的死按钮。
5. 第 1 课图注渲染成「图 1图 2」合并一行，且图自身的 label 从不显示。
6. FigureSpec 只有 objectCount 断言，无几何断言；实测 fig-67 的 y 轴刻度 7 破坏了 55px 等距（应在 474，实际 464）。

### 发布裁决
发布模式 = **全权委托**（人已明确禁止停下决策，且本 seed 由人发起，不受 fuse 限制）。草案集即刻发布，进入 cap5 逐张归档 → cap3 立批 0016 → cap4 开发 → cap6 收尾。
