# IntentMill Spec

## Intent

Give an authenticated learner a durable wrong-answer notebook for textbook exercises: every wrong occurrence can be found by UTC date and reopened at the exact original exercise for another submission.

## Scope

- Persist wrong automatically graded textbook exercise occurrences in a dedicated durable database table.
- Add a wrong-answer notebook entry to the existing profile dropdown.
- Add an authenticated notebook page inside the app shell with the current date-grouped view, book/exercise/time fields, and a clear single-view tab structure.
- Add exact exercise redo navigation and positioning to the existing textbook card route.
- Prove the real database-backed wrong-answer and redo flow at desktop and mobile sizes.

## Non-Scope

- Read checks, legacy relational quiz questions, English recitation, generated lesson content, and answer-key generation.
- Additional notebook views, filters, deduplication, deletion, resolution/mastery state, bulk redo, or analytics.
- Rewriting frozen charter files or migrating the whole retired Azure schema description in this ticket.
- Revealing correct answers or accepted forms in initial browser payloads.
- Adding a dependency, database client, service, or authentication mechanism.

## Requirements

1. A dedicated `"lemmadeck-schema".sr_textbook_mistakes` table stores one row per wrong automatically graded textbook exercise submission with:
   - `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`;
   - `user_id BIGINT NOT NULL` referencing `"lemmadeck-schema".sr_users(user_id) ON DELETE CASCADE`;
   - `book_id TEXT NOT NULL`, `lesson_id TEXT NOT NULL`, and `exercise_number TEXT NOT NULL`, with a check that all three trimmed identities are non-empty;
   - `occurred_at TIMESTAMPTZ NOT NULL DEFAULT now()`;
   - index `(user_id, occurred_at DESC, id DESC)` for deterministic newest-first reads.
2. The mistake table is durable user-visible history and is not derived from, linked to, or deleted with disposable `sr_content_answer_events`. Its `lesson_id` has no lesson-row deletion cascade.
3. The schema change is additive, idempotent, fully qualified to `lemmadeck-schema`, and lives in `ssot-schemas/db-schemas/stemrobin.sql`. Execution applies only this new LemmaDeck block inside a database transaction; any statement failure rolls back the block. The legacy Azure section is not retargeted or executed.
4. The textbook answer server operation resolves the book id from the existing textbook shelf authority. For an authenticated wrong auto-graded submission, it writes the existing content answer event and the durable mistake row in one database transaction. A correct or ungraded submission creates no mistake row.
5. A later correct submission never updates or deletes any previous mistake row.
6. The notebook read operation is server-only, scoped to the current authenticated learner, ordered newest first, and returns only the fields needed by the page.
7. The profile dropdown contains a localized wrong-answer notebook entry. Because `_app` is a public shell, the notebook child performs the same current-user redirect pattern as the existing authenticated `/learn` child.
8. The notebook page:
   - uses the existing app shell;
   - exposes one selected `By date / 按日期` tab using the established tab pattern so later view types have a stable entry point;
   - groups rows by UTC calendar date, newest first;
   - displays stored book id, printed exercise number, and an explicitly UTC-labelled timestamp;
   - uses the established empty-state pattern when there are no rows;
   - remains usable at desktop and mobile widths.
9. Each redo action navigates to the stored card id with typed search state for the exercise tab and printed exercise number. The card route opens that tab, visually identifies the exact exercise, scrolls it into the viewport after route restoration and MathLive layout, and leaves its answer controls usable.
10. Ordinary card navigation without redo search state still opens the reading tab and retains existing scroll-restoration behavior.
11. All correctness decisions remain server-side. Initial lesson/exercise browser data remains answer-key-free.
12. UI changes use only existing design-system tokens and patterns: `--sr-blue`, `--sr-green`, white/neutral surfaces, `--sr-font`, compact detail spacing, `.sr-tabs`, `.sr-empty`, profile-menu rows, Lucide icons, teal focus states, and the existing responsive shell.

## Critical Existing Contracts

- `app/src/lib/db.ts` is the only application database client and selects the active `LEMMADECK_DATABASE_URL` with quoted `lemmadeck-schema`.
- `app/src/lib/textbook-answer.ts` is the server-owned textbook grading boundary. The browser supplies answers but never receives hidden expected values before submission.
- `app/src/lib/textbooks.ts` is the textbook shelf and book-id authority; card ids must not be parsed ad hoc.
- `sr_content_answer_events` remains disposable and continues to serve its existing event/progress consumers unchanged.
- The `_app` parent is the public persistent shell; authenticated child pages such as `/learn` perform their own current-user redirect before loading private learner data.
- The generated route tree is build output; authored route behavior remains in route modules.
- New-page scroll restoration and the card's existing reading-tab default must not regress.

## Confirmed Decisions

- Use a dedicated durable `sr_textbook_mistakes` table; do not promote `sr_content_answer_events` to durable notebook storage.
- Add and apply only a fully qualified LemmaDeck schema block; leave the legacy Azure section untouched and record the wider documentation drift for boundary settlement.
- Preserve stored lesson/card identity without a lesson foreign-key cascade; retain the user-account deletion cascade.
- Store the book id at occurrence time and record each wrong submission as a separate occurrence.
- Use the existing tab and empty-state patterns, with only the date view active in this ticket.
- Acceptance verification may create records through the real app using the established test user, but cleanup may delete only exact ids created by that test run.

## Compatibility And Regression Constraints

- Existing read-check, progress, textbook rendering, answer feedback, English, knowledge-galaxy, and legacy quiz behavior remains unchanged.
- Existing correct, incorrect, and ungraded textbook verdict semantics remain unchanged.
- Profile menu logout and locale behavior remain unchanged.
- Chinese and English UI strings remain complete.
- No environment secret is printed, committed, or exposed to the browser.
- The schema apply must not execute legacy DDL against the active database or mutate existing rows.
